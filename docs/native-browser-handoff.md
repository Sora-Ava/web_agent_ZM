# 独立浏览器与人工接管

日期：2026-10-22。依据用户确认的有限改造方案实现。

## 使用

启动浏览器、独立登录或队列首次启动时显示 Chromium 窗口，继续与工作台预览共用原有 Page 和会话。工作台启动不受原 .env 中 HEADLESS=true 影响；不修改用户 .env。

手动操作前点击「人工接管」。若当前正在执行操作，先显示「等待当前操作结束」，在安全边界转换为「人工接管中」。此时可在原生窗口中操作；自动任务的后续步骤及排队任务等待。完成后点击「交还 Agent」。原本被任务暂停按钮暂停的任务保持暂停，接管期间仍可停止任务。

普通指令交还后重新观察页面，丢弃接管前尚未执行的模型建议，保留已完成动作证据。异常恢复同样丢弃接管前的旧定位建议，恢复调用上限保持两次。人工操作不自动录制，交还时提醒检查录制完整性。

Cookie 与页面不因接管切换而重建。人工操作可能切换账号，因此交还会清空程序的已验证账号记录；如显式登录提示未知会话，需要关闭并重新启动浏览器后执行登录。当前仍为单标签页操作，原生窗口无法限制人工点击，Agent 执行期间请避免手动操作。

## 实现范围

- BrowserSession 的控制状态、租约互斥、接管事件和页面版本。
- 启动/接管/交还 API、任务安全检查点及派发等待。
- 工作台状态按钮、人工操作时地址刷新；实时画面继续仅作预览。
- 原有固定来源标准流程限制继续生效。
