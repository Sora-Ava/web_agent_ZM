# 自然语言登录、凭据自动保存与流程录制设计

日期：2026-10-22  
状态：用户已批准实施；功能已实现并完成合成集成验收；独立审查和部署另行门禁。实际证据见 docs/natural-login-validation.md。

## 1. 已确认的目标

项目在 Windows 本机运行，供用户本人在内网使用。用户希望通过自然语言指挥 Agent 填写账号、密码并点击登录，将这些操作录制为标准流程，免去单独配置登录定位和 .env 凭据。保存后的标准流程正常回放不调用 LLM。

用户明确允许复用浏览器当前已登录会话，不再校验当前账号是否与录制账号相同。后续查询、导出使用当前会话的实际账号。程序仍必须通过流程的登录成功标识确认会话可用，不能仅因密码框消失而认定已登录。

## 2. 选定方案及范围

采用“本机提取凭据 + LLM 选择元素 + 程序填写 + 自动关联录制”的方案。相较于直接将密码交给模型，本方案仍支持自然语言操作，并能让模型调用、流程定义与普通历史记录只处理凭据引用。相较于原有独立登录面板，用户不再预先填写凭据名称和四类定位。

首版支持同一来源、同一页面上的账号框、密码框及登录按钮，以及分条或一条指令中完成这三个动作。保留现有“配置并执行登录”作为可选入口；标准流程的登录会话复用规则统一改为无需验证账号身份。

不增加人工键盘输入的自动录制、验证码处理、SSO 跨站登录、多标签页或多页面分段认证，不将本次改动扩展为通用密码管理器。

## 3. 用户操作过程

典型指令：

1. “访问 http://内部系统/login。”
2. “在账号框输入 operator。”
3. “在密码框输入 「示例密码」。”
4. “点击登录。”

也支持“账号是 operator，密码是 「示例密码」，填写后点击登录”。带空格、引号或特殊字符的值使用明确的引号或独立输入补充，程序不得 trim、改写大小写或猜测密码内容。

执行后历史显示“填写账号”“填写密码：••••••”“点击登录”，不显示真实值。保存标准流程时，系统自动将已录制的登录动作整理为一个登录组合步骤，展示定位摘要和“凭据已保存到本机”。用户确认流程及登录成功标识，无需手工配置凭据引用。

## 4. 页面观察与普通输入限制

现有程序主动从页面观察中过滤 type=password，并在提示词和执行器中禁止普通密码填写。本次改造解除对密码框元素本身的隐藏：模型可看到可见密码框的标签、角色、类型、定位、是否禁用，不读取输入框当前值。

隐藏字段、不可见字段仍不作为操作目标。普通业务 fill 继续与凭据填写分开：只有当前用户明确授权的凭据指令才能走凭据填写通道。网页内容或模型建议本身不能创建这项授权。

账号框可以是普通 text/email 输入框，实际填写前校验目标可见、唯一并可编辑；密码目标必须是可见、唯一的密码输入框。LLM 只能提出定位，不能修改本机已提取的凭据值或将密码用于其他操作。

## 5. 指令预处理与模型调用

凭据预处理位于命令提交入口，早于命令历史创建、事件发布和模型请求：

- 使用本机规则解析明确的“账号/用户名”“密码/口令”和填写意图，支持单字段、双字段及附带点击登录的指令。
- 将真实值保留在本机的命令上下文中；对外形成脱敏指令与短期引用，例如“向密码框填写本机凭据”。
- 模型根据脱敏意图与页面元素选择目标。执行器从命令上下文取值，忽略模型自行生成的凭据值，只执行该命令授权的字段。
- 如果指令表明涉及凭据，但字段、值边界或多个账号的关联不明确，先请用户补充；不把疑似原始凭据交给模型解析，也不猜测填写。
- 仅说“在这里输入 xxx”而未说明账号或密码，不能自动作为凭据录制。若页面目标只能是认证字段，先要求用户明确字段及值。

同一条指令的凭据只能用于提取时绑定的网站来源。自动执行期间跨来源跳转继续受原有约束；人工接管仍使用现有互斥机制。

## 6. 本机凭据存储

新增可写的本机凭据存储，与现有只读 .env 凭据适配器共同提供统一解析接口。自然语言录入不写入 .env，不覆盖既有凭据配置。

存储使用 SQLite 独立表保存引用 ID、来源、记录类型、创建时间及加密载荷。账号和密码均通过 Windows DPAPI 的当前用户保护后保存，密文之外不保存真实账号密码；数据库文件本身不视为整体加密。凭据默认只能在同一 Windows 用户与设备环境下解密。

凭据引用使用随机 ID，不能包含账号或密码。接口只提供引用、来源与就绪状态，不提供读取明文密码的接口。现有本地数据目录继续排除在 Git 提交之外。

账号和密码可以分条输入：以当前录制草稿、来源、登录表单及登录尝试为关联范围，保存待补全记录。只有字段关联唯一时才合并；出现多个表单或多个候选账号时，请用户明确。后续输入相同来源的新账号密码创建新记录，不覆盖已有流程版本引用的凭据。

成功填写后才保存对应凭据并记录引用。若填写成功而存储失败，明确反馈“已填写但未保存”，不声称已录制，也不自动重复填写。只完成一个字段或登录失败的草稿可以继续修改，但不能固化为完整登录组合步骤。

运行时新增凭据立即注册到统一脱敏器和持久化检查中，覆盖命令、异常、事件、模型请求、任务历史及多层 JSON 转义值。已有流程对明文凭据的拒绝规则保留。删除某个草稿或流程时不连带删除可能被其他版本、任务引用的凭据；首版保留这些加密记录，不增加凭据批量清理功能。

## 7. 录制、整理与数据结构

录制草稿新增凭据填写记录：目标定位、字段类型（username/password）、本机凭据引用及脱敏指令。真实值不进入 action.value、业务参数、草稿 instruction 或事件 payload。

点击登录后，记录提交按钮与页面变化。系统提出登录成功标识，例如业务首页导航或稳定的已登录区域，用户在保存流程时确认。标识必须可定位、唯一、可见且属于流程来源，不要求其文本证明具体账号。

整理标准流程时，将同一登录尝试中的账号填写、密码填写、提交操作替换为一个现有形式的 login 组合步骤，包含：

- 登录 URL 与流程来源；
- 自动生成的 credential_ref；
- username、password、submit、success 定位；
- reuse=true。

首版复用现有 schema_version=2 的登录组合结构，新增草稿记录类型和可写凭据存储即可，不需要为真实密码增加流程字段。标准流程中不会保留重复的普通账号/密码 fill。业务填写参数仍按原方式处理，凭据不作为参数默认值或文件名片段。

多条登录指令期间的普通导航或业务动作不被静默吞并。若动作无法可靠整理成同页登录组合步骤，保留草稿并提示调整，不伪造一个可回放的登录步骤。

未获得明确成功标识时，反馈“登录提交已执行，结果待确认”，不能仅凭按钮点击成功或 URL 变化声称登录成功。用户可以确认本次业务操作，但标准登录步骤要具备可重复验证的成功标识才能保存。

## 8. 标准流程回放与会话复用

每次执行登录组合步骤，按以下顺序处理：

1. 检查当前页面来源和登录成功标识。若匹配，直接复用当前会话，不检查 authenticated 账号记录，也不要求解密录制凭据。
2. 当前业务页没有成功标识时，访问录制的登录 URL，并检查重定向后的来源和成功标识。如果匹配，同样直接复用当前会话。
3. 若出现录制的登录表单，解析本机凭据，依次填写账号密码、提交并等待成功标识。
4. 若既无成功标识也无有效登录表单，停止并反馈；不将未知页面视为已登录。

凭据引用格式及来源仍需有效，但凭据存在性、可解密性检查延后到真正需要填写时，避免“当前会话已可复用却因凭据文件不可用而提前失败”。需要填写但凭据缺失或无法解密时，提示重新通过自然语言录入，不请求模型猜测。

程序不因“录制账号与当前账号不同”拒绝执行。reuse 的具体配置在 UI 中表达为“允许复用当前已登录会话”；reuse=false 时仍按显式重新登录要求执行，不在未出现登录表单时声称已重新填写凭据。

正常回放零 LLM。已有登录过期恢复继续使用流程内登录步骤，每行最多一次；结果不确定的导出不重复执行。对新录制登录和可选旧入口统一应用放宽后的当前会话复用规则。

## 9. 界面与已有数据

工作台继续使用现有自然语言指令框。凭据指令提交后立即清空输入，渲染脱敏历史，不在本地浏览器存储或 URL 中保留原始指令。命令事件返回前已完成服务端脱敏。

保存流程面板展示登录步骤、自动保存状态和成功标识确认，不额外要求用户创建凭据名称。任务历史和流程定义只展示引用与脱敏描述。

现有 .env 凭据及已保存登录流程继续可读，不进行批量导入或自动转换；新增流程使用本机可写凭据存储。新增表采用增量初始化，不删除既有数据库、导出文件或流程版本。已确认无需实现的历史配置转换仍不在范围内。

## 10. 验收标准

- 模型能看到密码框的类型、名称和定位；看不到密码框当前值与本次真实凭据。
- 分条与合并的自然语言登录均能完成填写和提交，无需先编辑 .env 或独立登录面板。
- 特殊字符、空格、中文密码保持原值；歧义指令请求澄清，不误填。
- 新凭据在首次模型请求前脱敏；日志、命令、事件、普通数据库内容、流程与任务快照不含账号密码明文。
- 保存的流程自动关联本机凭据；重启程序后仍可填写登录，正常回放模型调用数为零。
- 当前同来源会话满足成功标识时，即使账号记录缺失或与录制账号不同，也可复用；复用路径不依赖解密凭据。
- 业务页跳转回首页可复用；密码框消失、无关跳转、多重定位及跨来源跳转不能误判成功。
- 登录失败、凭据保存失败、缺失引用、解密失败与成功标识不明确均有确定反馈。
- 原有查询、无数据分支、下载、批量任务、人工接管和有限恢复规则保持有效；不产生重复导出。
- Windows 原生窗口、工作台端到端录制及离线回放均通过测试，测试使用合成凭据。
