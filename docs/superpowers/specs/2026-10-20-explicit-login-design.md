# 第二步：凭据参数与显式登录设计

日期：2026-10-20。状态：已由 [v2 设计](2026-10-20-explicit-login-design-v2.md) 替代，保留作设计历史；尚未修改产品代码。

## 目标与范围

在通用浏览器第一步之上，使用户能够通过界面配置并执行登录，确认后将登录作为标准流程的显式步骤。网址是普通参数；账号密码通过本机凭据引用参数选择。旧流程保持现有自动登录、版本、历史与批量执行行为。

本步仅支持账号密码表单、单个网站来源内的流程。多标签页、跨来源业务流程、SSO、验证码和网页内容问答不包含在内。

## 选择的实现方式

采用独立的登录步骤，内部完成导航、账号填写、密码填写、提交和成功验证。相比把密码作为普通 fill 参数，这样可以避免秘密进入模型工具参数、任务行和录制数据。相比仅增加一个“登录”按钮，显式步骤可以保存、编辑、批量回放并进行成功验证。

用户不需要在聊天中输入密码。网页运行表单选择凭据名称；实际账号密码仍放在本机 .env。首版不增加密码存储数据库或浏览器端凭据编辑器。

## 凭据配置与参数

- 保留 SITE_URL、SITE_USERNAME、SITE_PASSWORD，作为内置 default 凭据，兼容已有配置。
- 可选 CREDENTIALS_JSON 是本机 .env 中的命名凭据集合。每项包含名称、允许的网站来源、账号和密码；密码解析成 SecretStr，不在配置异常中回显原值。
- 新增参数类型 url 与 credential。credential 的值只允许已登记的引用名称，例如 default 或 erp_test，不接受原始密码。流程默认值和任务快照只保存引用。
- 凭据来源绑定 scheme、host、port。登录网址及实际填写时页面来源必须匹配流程与所选凭据；不同来源的重定向在填写前失败，不向新来源发送凭据。
- URL 参数可改变同来源内的登录路径。更换网站来源应建立或另存对应流程，不将本步扩成任意跨站回放。
- 只提供凭据名称、来源和是否就绪的元数据接口，不返回账号或密码。配置更新后重启服务生效。

## 流程结构与兼容

新增 execution_mode：缺省 legacy，新增显式流程使用 explicit。缺省字段使旧定义无需重写即可读取。

WorkflowStep 新增 login，与 action、condition 三选一。LoginSpec 包含：登录地址及可选 URL 参数绑定、凭据参数引用、账号框定位、密码框定位、提交按钮定位、登录成功定位。成功定位不能省略。

legacy 模式保持现有站点校验、自动登录和恢复逻辑。用户可在编辑器中选择“转为显式登录”，确认后产生新版本，在原步骤前加入登录步骤；旧版本和既有任务快照保持原样，不在升级时批量迁移。

explicit 模式不调用旧版隐式登录。程序执行登录步骤后才继续业务步骤；流程来源来自定义本身，而非全局 SITE_URL。新流程可以绑定其他网站，但每个流程仍限一个来源。仓库保存、任务提交、执行器和修复审核都需使用统一的模式/来源校验，避免只放开其中一层。

## 登录执行与会话复用

1. 校验参数类型、凭据存在及来源匹配，失败则不填写任何字段。
2. 当前页面来源匹配且成功标识唯一可见时，记录“复用已登录会话”，跳过重复登录。
3. 否则访问本步骤登录地址，再次检查实际来源。
4. 唯一定位账号框、密码框及提交按钮；密码框必须是 password 输入框。
5. 通过专用程序直接填写账号密码并提交，等待唯一的成功标识可见；再次确认来源。
6. 返回经过脱敏的成功/失败结果，记录登录步骤耗时；正常登录不调用模型。

同一任务内解析的凭据仅存在内存，不写入任务快照；批量每行保存引用并按需复用会话。凭据缺失、来源不符或登录失败作为全局故障停止队列派发，沿用显式重启队列入口。

explicit 流程后续步骤检测到登录失效时，最多重执行一次本流程指定的登录步骤并重建安全前缀，不退回 SITE_URL 登录。包含已导出动作或无法证明安全的前缀仍停止，不重复下载。登录步骤本身不交由模型修改凭据或自动重试提交。

## 页面入口与录制

工作台保留“启动浏览器”，增加“配置并执行登录”入口。登录面板提供地址、凭据选择、四类定位和成功标识；可用已有 SITE 配置填充 default 的初始值。提交后由程序执行，成功后录制一个登录步骤，不录制内部填写动作。

编辑器可增加、编辑和删除登录步骤，添加 URL 与凭据引用参数；运行面板和批量面板使用 URL 输入框及凭据下拉选择。凭据值不提供文本输入或 Excel 密码粘贴入口。

登录页面首次录制可按当前 HTTP(S) 来源建立显式草稿。来源切换时要求新建录制，避免与旧站点草稿混合；已有草稿保留。配置站点之外的新流程只走 explicit 校验。

本步先采用确定性登录面板，不新增让模型接收凭据的登录工具。自然语言继续负责导航与非敏感操作。

## 脱敏与文件名

所有已加载凭据的账号与密码加入统一脱敏器；覆盖多层 JSON 转义。模型提示、工具反馈、事件、错误和参数建议都使用统一脱敏，不序列化解析后的凭据对象。

任务、步骤、修复、草稿和流程数据只保存引用与定位。参数建议不改写登录步骤。导出文件名不包含 credential 参数、账号或密码；URL 参数也不直接拼入文件名，避免认证字段和过长路径。

密码框继续从通用页面观察中排除。实时画面仍仅本机观看，密码由网页输入框掩码显示。异常不返回 Playwright 原始调用日志或 Pydantic 原始秘密输入。

## 验收要求

- 原有完整测试通过，旧流程不修改仍可自动登录、查询、导出、恢复与查看历史。
- 新显式流程在非 SITE_URL 的受控演示站完成登录和导出，正常执行零模型。
- 同一会话两次运行不重复提交登录；无成功标识、定位歧义、错误凭据明确失败。
- 缺失引用、原始密码误填、来源错配及跨站重定向在填写前被拒绝。
- 新流程、任务、数据库文本、事件、错误和捕获的模型请求均不包含合成账号密码，含引号、反斜线等转义场景。
- 登录过期使用本流程登录步骤恢复；不重复导出，登录失败停止派发。
- 网页端完成配置登录、确认固化、参数选择、批量运行及旧版本兼容。
- 升级前备份并校验 .env、自定义检查脚本、数据库和导出文件；不自动修改用户凭据配置。

## 实施顺序

先实现凭据解析和脱敏，再扩展流程模型与兼容校验，然后接入登录执行/恢复，最后完成登录面板、录制、参数表单、浏览器验收和 GitHub PR。审阅确认后另写逐项实施计划。
