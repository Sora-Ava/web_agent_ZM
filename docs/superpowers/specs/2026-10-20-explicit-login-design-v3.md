# 第二步设计 v3：统一流程登录与凭据参数

日期：2026-10-20。状态：待审阅，仅修改设计文档。本文替代 v2；按用户确认移除旧配置导入、旧流程转换和历史格式兼容要求。产品实现尚未开始。

## 目标与判断

浏览器始终以空白页启动。登录是用户编排的流程内容：打开指定地址、使用凭据填写账号密码、提交并确认登录成功。固定网址登录也可以单独保存为标准流程。

统一由流程中的显式登录步骤执行，不保留固定站点的隐式登录分支。当前为非正式系统，没有需要转换的旧配置或流程，本步直接采用新配置和新流程结构。

不开发旧配置导入、旧流程转换、旧定义只读适配或旧版本运行兼容。既有浏览器操作、队列、历史管理、文件下载和有限恢复能力继续服务于新流程结构。取消兼容要求不代表自动删除本机已有数据库、文件或改写 .env；开发验收使用新格式测试数据。

## 一套流程模型

新流程使用 schema_version=2，不增加 execution_mode。步骤支持普通操作、条件和登录，三者互斥。没有登录步骤的流程按普通网页流程执行，不检查登录，也不执行任何隐式登录。

登录是可展开查看的组合步骤 LoginSpec，包含：

- 登录网址：固定值或 URL 参数绑定。
- 凭据引用：固定的本机凭据名称，或 credential 参数绑定。
- 账号框、密码框、提交按钮及登录成功标识的定位。
- 会话复用策略，默认满足成功标识时复用。

程序将组合步骤展开为导航、填写、提交与等待，内部敏感动作不会被单独录制。成功标识必须填写，不能以“点击了登录按钮”代替登录成功。

页面中显示完整登录步骤，用户可以编辑、移动或删除。删除登录步骤后该流程不会再由系统补做登录。

## 登录流程与业务流程

独立“系统登录”标准流程可以只包含一个登录步骤。用户先运行它，再执行查询导出流程，可以复用浏览器会话。

需要一键完成登录和业务时，可在业务流程编辑器中“从已有流程复制登录步骤”，将选定版本中的登录配置及关联参数复制进当前流程，再确认保存新版本。复制后为独立快照，源登录流程修改不会自动改变业务流程。

本步不新增嵌套流程调用、递归和子流程版本解析。独立登录与业务内嵌登录使用相同的步骤结构和执行代码，并非两套登录机制。

## 凭据与 URL 参数

账号密码继续保存在本机 .env。可配置 CREDENTIALS_JSON 命名凭据集合，每项包含名称、允许的网站来源、账号和密码；界面只返回名称、来源和就绪状态。

登录配置统一使用 CREDENTIALS_JSON，不读取 SITE_URL、SITE_USERNAME、SITE_PASSWORD 或全局登录定位作为登录依据。登录网址和各元素定位属于流程步骤。更新 .env.example 和配置说明，实际 .env 由用户自行填写，不自动转换或覆盖。

新增 url 与 credential 参数类型。credential 参数只选择本机已登记的名称，不输入或持久化原始密码；选择不同引用即选择不同账号密码组合。运行表单和批量表格使用凭据下拉列表，任务快照只保存名称。

每个流程绑定一个 HTTP(S) 来源。URL 参数可改变同来源路径；登录实际页面来源、流程来源和凭据允许来源必须一致。跨来源重定向在填写前终止。更换网站来源需建立或另存对应流程；多来源业务流程留待后续。

当前普通浏览器指令仍可跨站访问，但保存为本步标准流程时只允许单来源。来源来自流程定义，与全局固定站点无关。

## 执行与会话复用

1. 执行前校验参数、凭据引用和来源，失败时不填写字段。
2. 只有当前来源匹配、成功标识唯一可见，且本会话曾由同一凭据引用成功登录时，才复用已登录会话。
3. 更换凭据引用不默认为已经切换账号。本步不自动猜测退出登录入口；若已有其他账号会话则停止，并提示关闭浏览器后重新启动或先显式退出。
4. 需要登录时打开本步骤地址，再检查实际来源，唯一定位表单；密码目标必须是 password 输入框。
5. 程序直接填写、提交，等待成功标识唯一可见，并再次检查来源。正常登录零模型调用。
6. 登录结果与耗时写入步骤记录，秘密值不进入记录。账号相同的后续查询可复用会话，无需每次登录。

同一批任务的凭据解析仅存在内存；重启后未完成任务标记中断，不恢复秘密。凭据缺失、来源错误、账号会话冲突或登录失败停止后续队列派发，沿用显式重新启动队列入口。

## 登录失效恢复

恢复仅使用当前流程已执行的登录步骤，依据该步骤的表单定位识别登录页。每行最多重新登录一次，成功后重建安全业务前缀。

没有登录步骤的流程不自动寻找或调用其他登录流程，遇到认证问题时失败并提示用户先执行登录流程或在业务流程中加入登录步骤。执行过独立登录流程，不代表业务流程自动获得隐藏的登录依赖。

前缀包含导出或无法证明可以安全重放时停止，不重复下载。登录提交失败不调用模型修改凭据或自行重试；一般业务定位恢复沿用原有限机制。

## 页面与录制

工作台保留“启动浏览器”，增加“配置并执行登录”。面板提供网址、凭据选择、账号/密码/提交/成功定位。用户从本机凭据列表选择引用并配置页面定位。执行成功后录制一个登录组合步骤，可单独保存，也可继续录制业务。

编辑器支持添加登录步骤、复制已有登录配置、URL/凭据参数绑定。首次录制按当前网站建立草稿；换来源需新建录制，避免不同站点内容混合。

本步先用确定性登录面板，LLM 继续负责导航及非敏感业务操作，不接收或填写实际凭据。多标签页、SSO、验证码、密码修改和任意流程嵌套不在范围内。

## 脱敏与持久化

所有凭据的账号密码加入统一脱敏，覆盖多层 JSON 转义；配置解析错误不回显原始输入。模型请求、日志、事件、任务行、草稿、流程定义和修复内容只含引用及非敏感定位。

原始秘密仅在凭据解析与专用填写代码中使用。普通参数接口不接受密码参数类型，凭据字段只能选择有效引用。参数建议不改写登录步骤；文件名排除凭据与 URL 参数。密码框继续不进入通用页面观察，截图仅本机展示，错误不返回 Playwright 原始调用日志。

## 验收标准

- 空白启动保持不变，登录仅由显式步骤触发，不存在固定站点隐式登录入口。
- 使用新 .env 凭据配置，创建独立登录标准流程，确认后运行成功，正常执行零模型。
- 在业务流程中配置或复制登录步骤，完成登录、查询、无数据分支和导出；复制后的配置保持独立快照。
- 不同网站的单来源流程可分别配置和运行，不依赖全局固定网址。
- 同一凭据连续查询不重复登录；更换凭据不会误用旧账号会话。
- 缺失凭据、错误来源、跨站重定向、表单歧义和失败登录均得到确定结果。
- 登录过期使用流程内的登录步骤恢复，安全前缀重放、不重复导出及队列故障保护通过回归。
- 捕获模型请求、数据库、日志、事件与异常，验证其中无合成账号密码，覆盖转义与多个凭据场景。
- 网页验证配置登录、录制固化、参数选择、批量运行、任务历史、文件下载和删除。
- 回归测试按新模型更新登录场景，保留通用浏览器、队列控制、版本不可变和下载管理验证；不测试已移除的旧登录方式和迁移能力。
