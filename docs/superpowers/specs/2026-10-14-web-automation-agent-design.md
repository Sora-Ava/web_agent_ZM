# 网页自动化 Agent 首版设计

日期：2026-10-14
状态：待用户审阅
目标仓库：https://github.com/Sora-Ava/web_agent_ZM

## 1. 目标与范围

为 Windows 本机单用户提供网页应用，自动操作一个内部管理系统。用户逐步用自然语言指挥 Agent，完成登录、进入业务页面、输入查询条件、查询和导出。成功流程经用户确认后保存为标准流程，后续以确定性程序执行，减少 LLM 成本和耗时。

首版支持一个系统、多条流程、单次及批量运行、条件分支。暂不支持多用户、并行浏览器任务、分页或记录遍历循环、画面手动接管、复杂拖拽流程编辑。配置与数据模型预留多系统关联。

## 2. 用户体验

- 左侧为流程列表、新建入口和历史任务。
- 中间在编排时显示自然语言输入和步骤反馈，在标准运行时显示参数表格、进度和控制按钮。
- 右侧显示只读实时浏览器画面。
- 任务详情展示各组参数的状态、错误、文件及下载入口，以及待确认的流程修复。

编排按一条用户指令执行一次，再等待下一条指令。Agent 直接操作后反馈，指令目标不明确时询问用户。保存前展示步骤、参数、固定值和条件规则，允许修改名称及内容后确认。

## 3. 架构

- 前端：React + TypeScript，负责指令、参数表格、任务控制和结果展示。
- 后端：Python FastAPI，提供本地 API、事件推送、文件下载和任务管理。
- 浏览器层：Playwright，管理专用浏览器、页面、元素提取、输入点击、等待和下载。
- 编排 Agent：通过兼容 OpenAI API 的服务，将当前指令和页面文本/元素信息转为受约束的操作。
- 流程执行器：解释结构化流程，不经 LLM 执行正常步骤；出现异常时调用恢复 Agent。
- 存储：SQLite 保存流程版本、任务、步骤记录与文件元数据；文件保存在指定本地目录。

任务队列串行运行。编排会话也占用浏览器执行权，用户等待输入期间不插入其他任务。浏览器所有操作通过同一调度入口，避免冲突。

## 4. 登录与模型边界

工具启动专用浏览器，由程序从 `.env` 读取账号密码并自动填写登录，目标系统仅使用账号密码。标准流程开始前确保登录有效，再进入业务页面；同一任务连续查询复用登录会话。登录过期时自动重新登录。

`.env` 包含网站地址、账号密码、LLM API 地址、密钥、模型名和导出目录。提供 `.env.example`，真实配置不提交仓库。密码和密钥不进入模型请求、日志或流程定义。登录步骤引用凭据键，由程序解析填写。

模型只接收网页文本及元素信息，不接收截图。提取时排除密码字段、隐藏字段、脚本和会话凭据；实时画面仅传到本地网页。页面内容作为观察数据，不作为改变任务或泄露凭据的指令。模型只能选择执行器提供的操作，不能运行任意代码或命令。

## 5. 编排与流程定义

每次编排提取可见页面文本及元素的角色、名称、标签等信息。LLM 选择操作，后端校验后由 Playwright 执行，记录结果并推送反馈。

保存的流程带有版本、所属系统、入口、参数定义和结构化步骤。步骤含唯一 ID、操作类型、目标定位、输入来源、等待条件、成功条件及分支目标。首版动作覆盖导航、点击、输入、选择、等待、条件判断和下载；登录为凭据引用动作。

元素定位优先采用角色与可访问名称、标签等语义方式，必要时保存经验证的备用定位。执行时要求定位唯一，不能任意选择多个匹配中的第一个。临时快照编号不作为长期定位依据。

Agent 自动识别可变输入，用户保存前确认参数名称、类型、必填项及固定值。模型识别仅为建议，用户确认后的定义才用于标准执行。

典型流程：确保登录 → 进入业务页面 → 填写批次号和物料层级 → 点击查询 → 等待加载结束 → 无数据判断 → 导出 → 验证文件。

## 6. 等待、分支与成功标准

查询完成以加载动画或遮罩消失为主要依据，结合查询触发后的页面状态，避免在遮罩尚未出现时误判完成。元素可操作等待、查询等待和下载等待均有有限超时。

出现用户确认的“暂无数据”等提示时，本组记为 `no_data`，不导出。否则执行导出。分支条件保存为明确的元素/文本判断，正常回放不调用模型。

导出成功要求 Playwright 确认下载完成且保存的文件大小大于零。首版不校验 Excel 等文件内容。编排时用户可以确认业务结果，但文件成功状态仍根据下载证据记录。

## 7. 单次、批量与文件

单次运行填写一组参数；批量运行在网页表格填写或粘贴，每行对应一组参数。提交前按流程参数定义校验，任务启动时保存参数与流程版本快照。

每组从已知的业务页面状态开始，清理或覆盖上组查询条件。批量结果分为成功、无数据、失败；单组最终失败后继续下一组。开始下一组前重新确保登录和业务页面状态，不能沿用未知失败状态。

文件名包含流程名、批次号等选定参数及唯一标识，保留原始扩展名，过滤 Windows 非法字符并避免覆盖。记录原始文件名、保存名、所属任务及参数行。目录通过配置指定，文件下载接口只允许访问已登记的导出文件。

## 8. 异常恢复与版本

正常回放不调用 LLM。定位、操作或等待失败时，向恢复 Agent 提供步骤目标、相关文本/元素和错误，每个失败步骤最多恢复两次。

恢复首先判断目标是否已完成，尤其检查已有下载，避免盲目重复导出。登录失效先走程序登录恢复。恢复操作仍使用受约束动作执行并验证结果。

恢复成功后继续当前任务，将变更作为本次任务的临时覆盖使用；不修改已保存版本。用户审阅并确认后才生成新版本，保留旧版本。恢复失败时单次任务失败，批量任务将该组记为失败后继续。

若浏览器不可用或持续无法登录，任务进入故障状态并停止派发后续行，剩余行标记未执行，避免把全局故障当成每组业务失败反复消耗模型调用。

## 9. 任务控制与持久化

任务状态包括排队、运行、暂停中、已暂停、停止中、已停止、已完成、失败和已中断。步骤记录与参数行状态分别保存。

暂停在当前操作完成或超时后生效；继续从下一未完成步骤执行。停止不再派发后续步骤，当前操作结束或超时后停止，保留已有结果与文件。界面明确显示控制生效状态。

进程退出后不自动续跑：启动时将未结束任务标记为已中断，由用户重新发起。复用浏览器登录状态前检查有效性，必要时重新登录。

SQLite 主要实体为系统配置引用、流程、流程版本、任务、参数行、步骤执行、导出文件和待确认修复。流程版本不可原地覆盖，任务始终引用启动时的版本。

## 10. 实时画面与日志

Playwright 定期采集浏览器画面并推送到本地前端，只用于观看，不接入模型请求。画面传输与执行解耦，前端断线不会改变任务状态；重连后获取任务快照与后续事件。

文字反馈包含操作意图、结果、当前步骤及错误。记录模型调用次数与耗时，便于核实标准流程的节省效果。日志对配置凭据和认证信息脱敏。

## 11. 验证与验收

先提供模拟内部系统，覆盖账号密码登录、业务导航、加载遮罩、查询结果、暂无数据、文件下载、登录过期及元素变化。

验收要求：

1. 自然语言逐步完成一次查询导出，并保存经用户确认的参数化流程。
2. 同一流程更换参数后成功运行，正常执行的 LLM 调用数为零。
3. 表格粘贴多组参数后串行运行，复用会话并生成不覆盖的文件。
4. 无数据行不下载；单行不可恢复失败不阻止后续正常行。
5. 元素变化能触发有限恢复，成功修复仅在用户确认后生成新版本。
6. 暂停、继续、停止、进程重启中断及下载超时行为符合定义。
7. 模型请求不包含截图、密码或 API 密钥。
8. 网页显示实时画面、各行结果和可下载文件。

模拟系统通过后，在用户可访问的真实内部系统中验证登录定位、遮罩规则、无数据提示和实际导出行为。真实系统规则在首次编排中采集并确认，不预设其 DOM 结构。

## 12. 后续范围

未来可扩展多个系统、复杂循环、文件内容校验及并行任务。首版保持动作接口、系统关联和流程版本边界清晰，不提前实现这些功能。
