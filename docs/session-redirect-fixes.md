# 会话复用与流程导航边界修复

日期：2026-10-21。

## 修复行为

- 已验证的同一凭据身份不会因当前业务页缺少成功标识而提前清除。访问登录网址后再次检查成功标识与来源，允许复用已验证身份；未知身份仍失败。确认需要重新填写凭据时，先清除旧身份，避免失败登录保留错误认证记录。
- 标准流程使用 Chromium CDP Fetch 检查主页面每一跳导航，跨来源请求在发出前终止；操作完成后再次检查最终来源。入口、恢复入口和点击/回车触发的导航同样受限。使用 CDP 是因为 Playwright route 不会重新拦截同一 HTTP 重定向链的每一跳。
- 来源越界失败携带 scope_violation 标志，恢复层不使用下载等完成证据覆盖、不重新登录或尝试模型修复。已经触发的导出保留 effect_started 状态。
- 通用浏览器仍允许跨站访问，同来源的标准流程重定向继续成功。没有引入旧流程或配置转换。

## 验证

- 修复前真实本地 HTTP 重定向测试复现入口、最后导航和点击跳转误成功，以及已验证同账号会话被误拒绝。
- 第一轮完整回归：130 passed，241.13 秒。
- 新增最终来源兜底及恢复证据不可覆盖来源失败的测试后，再次运行导航边界与全部恢复测试，34 passed，76.57 秒。
- 新增 10 项测试包含已知/未知身份、阻断前外站零请求、入口提前终止、最后步骤失败、点击跳转、通用跨站、同来源跳转、最终地址兜底及恢复证据保护。
- 独立代码复查无未解决问题。

## 限制

当前执行器使用 Chromium；标准流程仍是单来源、单标签页模型。导航拦截覆盖每个等待中的操作，不扩展为常驻浏览器网络策略。
