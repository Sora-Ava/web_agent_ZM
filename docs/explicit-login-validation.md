# 显式登录与凭据参数验收

日期：2026-10-20。实现依据为已确认的第三版设计，未开发旧配置导入、旧流程转换或隐式登录兼容。

## 已交付

- 本机 CREDENTIALS_JSON 命名凭据解析、仅返回引用名称/来源/就绪状态的接口；统一处理账号密码及多层 JSON 转义脱敏。
- schema_version=2 登录组合步骤，网址和凭据可绑定参数；执行器只运行流程中的登录，不依赖 SITE_URL 等全局登录配置。
- 配置并执行登录面板、登录录制与确认固化、编辑器增加/复制登录步骤、单次/批量 URL 和凭据选择。
- 登录先验证来源、唯一表单与密码框，填写时原子检查当前来源；拒绝跨来源导航。只复用同一引用已验证的会话。
- 登录过期恢复仅使用当前流程已执行登录步骤，每行最多一次；不重放含导出的前缀，已触发但结果不确定的导出不重试。
- 默认新库 data/agent-v2.sqlite3，原数据库和文件保留但不转换，用户 .env 与自定义检查脚本保持原样。

## 验证证据

- 完整测试：122 passed，229.96秒；TypeScript/Vite 构建通过，源码与本机安装构建产物一致。
- 网页端验证配置登录、录制固化、单次/批量运行、复制参数重新标识及源版本不变。
- 受控跨来源网页验证、错误密码、空白启动、无登录步骤不隐式认证、过期恢复、暂停/停止、下载证据、历史/文件删除及恢复审核回归通过。
- 独立审查发现的账号片段持久化、认证恢复重复导出和非成功页换账号三项问题，均先复现失败再修复通过；补充多层转义账号拒绝存储测试。
- 本机安装使用进程级临时演示凭据和独立测试库验收：独立登录成功、复用成功、业务两行分别 success/no_data、导出1个文件、模型调用0次，数据库无演示账号密码原值。
- 验收后移除临时环境并正常启动，凭据列表恢复为空，启动停留 about:blank，使用正常新库路径；再次校验原 .env、自定义脚本、原库和既有导出文件保持不变。

## 使用前配置与限制

用户需参照 .env.example 将 CREDENTIALS_JSON 添加到自己的 .env 后重启，随后在登录面板配置网址与四类定位。不会自动转换原 SITE_* 字段。演示账户为 operator / demo-password，仅用于本地模拟系统。

不同凭据账号切换使用关闭并重新启动浏览器，以确保客户端旧会话清理；不推断网站退出是否已经完成。每个流程单一来源；不支持多标签页、SSO、验证码或任意子流程嵌套。真实内部系统仍待用户配置及验收。
